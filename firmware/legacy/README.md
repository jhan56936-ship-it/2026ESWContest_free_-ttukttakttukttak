# 개발 초기의 스케치 (개발 과정 기록용 보관)

`sketch_jul10a_v2.ino` — 개발 초기에 기기에 올려 쓰던 스케치입니다. **40줄**입니다.
무엇이 왜 달라졌는지 줄 단위로 비교할 수 있도록 지우지 않고 남겨 둡니다.

```cpp
if (digitalRead(BUTTON_1_PIN) == LOW) {
  Serial.println("Button1");
  delay(200);
  while (digitalRead(BUTTON_1_PIN) == LOW) { delay(10); }   // 손 뗄 때까지 정지
}
```

## 이 코드가 못 하는 일

| 문제 | 왜 문제인가 |
|---|---|
| **폴링 + `delay()`** | 버튼을 누르고 있는 동안 CPU가 `while` 안에 갇힙니다. 그 사이 2·3번 버튼은 아예 안 읽힙니다 |
| **오류 검출 없음** | `"Button1\n"` 평문. 비트 하나가 뒤집혀도 그대로 실행 → 화면으로 확인하지 않는 사용자에게 잡음 한 번이 그대로 앱 실행 |
| **중복 방지 없음** | 같은 신호가 두 번 오면 두 번 실행. 그래서 앱이 3초 디바운스를 대신 떠안고 있었음 |
| **길게 누름 불가** | 누른 순간 바로 보내고 손 뗄 때까지 대기 → 짧게/길게 구분이 원리적으로 불가능 |
| **폰이 죽으면** | 기기는 계속 혼자 떠들 뿐, 못 받고 있다는 사실조차 모름 |

## 지금은 어떻게 바뀌었나

| | 초기 스케치 (이 파일) | 완성된 펌웨어 (`../vibekey_firmware/`) |
|---|---|---|
| 입력 | `loop()` 폴링 + `delay()` | GPIO 인터럽트 → 큐 → FreeRTOS 태스크 |
| 떨림 방지 | **안드로이드**의 3초 디바운스 | 기기 상태머신 (25ms 디바운스 + 1.2초 가드) |
| 전송 | `Serial.println("Button1")` | 프레임 + CRC16 + SEQ + ACK + 재전송 3회 |
| 동시 입력 | 한 버튼을 누르고 있으면 나머지가 안 읽힘 | 인터럽트라 세 개가 동시에 살아 있음 |
| 줄 수 | 40줄 | 771줄 (+ PC에서 도는 테스트 43개) |

배선은 **이 파일과 완전히 같습니다**(D0·D1·D2). 부품이 늘어난 것은 없고,
이미 만들어 둔 기기에 **펌웨어만 올리면 됩니다.**
