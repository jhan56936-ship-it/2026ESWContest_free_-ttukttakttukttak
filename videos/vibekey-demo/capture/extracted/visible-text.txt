# 바이브키 시연영상 스토리보드 (v1 초안)

- **용도** 2026 임베디드SW 경진대회 자유공모 · 제출용 시연영상
- **길이** 2분 55초 (요강 3분 이내)
- **화면비** 16:9 / 1920×1080 / 30fps
- **핵심 메시지** “어르신도 버튼 세 번이면 끝”
- **톤** 담백하게. 과장 광고 아님. 심사위원이 보는 기술 문서의 영상판.

## 1. 문제 — 0:00–0:22

| 컷 | 시간 | 화면 | 내레이션 / 자막 |
|---|---|---|---|
| 1-A | 0:00–0:06 | 검은 화면에서 폰 화면만 밝게. 앱 아이콘이 빽빽한 홈 화면. 손가락이 올라왔다가 멈추고, 다시 내려간다. | (무음) |
| 1-B | 0:06–0:14 | 같은 화면. 아이콘들이 하나씩 흐려지며 이름이 안 읽히게 blur 처리. | **“전화 한 통 거는 데 화면 세 번, 아이콘 스무 개.”** |
| 1-C | 0:14–0:22 | 화면 꺼짐. 어둠 속에 문장만. | **“익숙하지 않은 사람에게는 그게 벽입니다.”** |

- 모션: 1-B의 blur는 아이콘별 0.08초 시차(stagger)로 번져 나가게. 한꺼번에 흐려지면 연출이 싸구려로 보인다.
- 소리: 1-A 무음 → 1-C에서 저음 한 번. 정적을 먼저 만들어야 2번의 등장이 산다.

## 2. 해답 — 0:22–0:40

| 컷 | 시간 | 화면 | 내레이션 / 자막 |
|---|---|---|---|
| 2-A | 0:22–0:28 | **[실물 사진]** 기기 전체 샷. 어둠에서 빛이 들어오듯 페이드인. | **“바이브키.”** |
| 2-B | 0:28–0:34 | **[실물 사진]** 버튼 3개 클로즈업. 각 버튼 위로 라벨이 하나씩 떠오름 — `1 전화` `2 문자` `3 길찾기` | **“버튼은 세 개뿐입니다.”** |
| 2-C | 0:34–0:40 | 기기 → USB 케이블 → 폰. 케이블을 따라 빛이 흐른다. | **“USB로 꽂으면 그걸로 끝. 앱 설정도, 인터넷 연결도 필요 없습니다.”** |

- 2-B의 라벨은 사용자가 직접 바꾸는 값이라는 걸 4번 구간에서 회수한다.
- 모션: 케이블 광선은 0.9초에 걸쳐 기기→폰 방향. 방향이 중요하다(입력이 어디서 오는지).

## 3. 실사용 시연 — 0:40–1:30

실제 촬영본이 가장 설득력 있는 구간. **화면 녹화 + 손 촬영을 한 프레임에** 담는다(폰 화면은 실기기 녹화 합성).

| 컷 | 시간 | 화면 | 내레이션 / 자막 |
|---|---|---|---|
| 3-A | 0:40–0:52 | 1번 버튼 누름 → 폰이 진동 → 전화 앱이 번호까지 채워진 채 열림. 우측 상단에 `짧게 누르기` 배지. | **“1번을 누르면 전화 앱이 열립니다. 번호까지 채워진 채로요.”** |
| 3-B | 0:52–1:04 | 2번 버튼 → 문자. 같은 리듬. | **“2번은 문자.”** |
| 3-C | 1:04–1:18 | 3번 버튼을 **길게** 누름. 배지가 `길게 누르기`로 바뀌고 진동 패턴이 다름 → AI 도우미 화면. | **“같은 버튼도 길게 누르면 다른 일을 합니다. 버튼 3개로 6가지.”** |
| 3-D | 1:18–1:30 | 설정 화면에서 버튼에 다른 앱을 끌어다 놓는 장면. | **“무엇을 넣을지는 쓰는 사람이 정합니다.”** |

- **진동은 폰이 한다.** 기기에는 진동 모터가 없다. 내레이션에서 “기기가 떨린다”고 하면 거짓말이 되니 주의.
- 각 컷은 **누름 → 진동 → 앱 열림**의 3박자를 지킨다. 리듬이 반복되어야 “항상 이렇게 된다”가 전달된다.

## 4. 안을 열면 — 1:30–2:25

| 컷 | 시간 | 화면 | 내레이션 / 자막 |
|---|---|---|---|
| 4-A | 1:30–1:38 | 기기 사진 위로 회로가 선으로 그려짐. 버튼 3개 → MCU → USB. | **“안에는 ESP32-S3가 들어 있습니다.”** |
| 4-B | 1:38–1:52 | 타임라인 다이어그램. 버튼 눌림 → `ISR` → 큐 → `입력 태스크` → `프로토콜 태스크` → USB. 각 단계에 점이 흐른다. | **“버튼이 눌리는 순간을 인터럽트로 잡고, FreeRTOS 태스크 두 개가 나눠서 처리합니다. 채터링은 여기서 걸러집니다.”** |
| 4-C | 1:52–2:08 | VKP 프레임이 바이트 블록으로 조립됨: `AA │ SEQ │ TYPE │ LEN │ 데이터 │ CRC16 │ 55` | **“전선으로 그냥 보내지 않습니다. 직접 정한 프레임에 담고, CRC로 서명하고, 폰이 잘 받았다고 답할 때까지 다시 보냅니다.”** |
| 4-D | 2:08–2:18 | 프레임 하나가 전송 중 비트 몇 개가 붉게 뒤집힘 → 폰 쪽에서 `✕ CRC 불일치` → 버려짐 → 재전송 → `✓` | **“한 비트라도 틀어지면 버립니다. 잘못 눌린 척하는 신호가 앱에 닿지 않도록.”** |
| 4-E | 2:18–2:25 | 워치독 아이콘. 기기가 멈춤 → 5초 → 자동 재시작 → 재시작 원인이 폰에 표시됨. | **“기기가 멈추면 스스로 되살아나고, 왜 멈췄는지 폰에 보고합니다.”** |

- 4-C·4-D가 이 영상의 **기술적 하이라이트**다. 여기에 가장 공들일 것.
- 4-D의 비트 뒤집기는 실제 단위 테스트에 있는 시나리오다. 지어낸 그림이 아니라는 점을 자막 하단에 작게 표기: `firmware/test/test_vkp.cpp`

## 아직 막힌 것

1. **Node.js 미설치** — hyperframes 렌더러가 못 돈다. `brew install node`
2. **실측값 2개** — 기기를 꽂고 측정해야 5번 구간이 완성된다.
3. **앱 화면 녹화** — `VibeKey-3.1.apk`를 폰에 설치해야 찍을 수 있다.
